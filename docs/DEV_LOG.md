# 今日热搜 · 开发日志

## 项目信息

- 项目名称：Mini Hot Hub（迷你今日热榜）
- 技术栈：React + TypeScript + Vite（前端）+ Node.js + Express（后端）
- 目标平台：微博、知乎、B站、抖音、小红书、澎湃新闻、36氪、虎扑、GitHub
- 开发方式：Vibe Coding（AI 辅助开发）
- 开发工具：Claude Cowork

## Step 1.5：差异化分析（RESEARCH.md 更新）

**日期**：2026-06-03

**做了什么**：
- 阅读了用户提供的《市场与用户研究报告》和《热搜聚合应用系统调研》两份文档
- 发现关键洞察：2026 年所有竞品普遍缺少 AI 能力，这是最大的差异化窗口
- 新增了一个重要开源参考项目：newsnow（20.4k stars），比 DailyHotApi 更现代
- 确定了 3 个核心差异化功能：AI 推荐卡片、AI 分类标签、热度飙升标记

**关键决策**：
- MVP 平台缩减为 8 个（小红书后续扩展）
- AI 模型选择 DeepSeek V3.2（月成本约 15~25 元）
- AI 调用与热搜抓取绑定在同一定时任务中，结果统一缓存
- AI 功能做降级处理：AI 挂了不影响基础热搜展示

**遇到的问题**：
- 暂无

**产出文件**：`RESEARCH.md`（更新版）

## Step 4：技术设计文档（TECH_DESIGN.md）

**日期**：2026-06-05

**做了什么**：
- 基于模板结构，结合 PRD（v3）、RESEARCH.md、DESIGN.md（v2）编写完整技术设计文档
- 定义了完整数据模型：HotItem、HotPlatform、AIFeatured、AIRecommend、RankingItem、HotResponse
- 编写了 GET /api/hot 接口的 JSON 示例（成功响应 + 单平台失败 + AI 不可用 三种场景）
- 绘制了 ASCII 架构图（浏览器 → Express → 缓存 → fetch 平台 → AI 服务 → 返回）
- 明确了缓存策略（内存 Map、TTL 5~10 分钟、三种 key）和降级策略表

**关键决策**：
- 接口设计：一个 GET /api/hot 返回全量数据（AI + 平台），前端不需要多次请求
- AI 输出拆为三块：featured（今日最热+热点速览，section 字段区分）、recommendations（个性推荐）、ranking（综合热榜）
- AI 10 秒硬超时，超时等同不可用
- 项目结构确定：client/ + server/ 双目录，server 下拆 routes/services/ai/utils 四层

**遇到的问题**：
- 暂无

**产出文件**：`TECH_DESIGN.md`
