# 今日热搜 · 产品需求文档（PRD）

## 产品概述

「今日热搜」是一个 **AI 增强的多平台热搜聚合网站**。聚合微博、知乎、B站、澎湃新闻、36氪、虎扑、GitHub、今日头条共 8 个核心平台的实时热榜（抖音尽力接入，可降级），并通过 AI 实现跨平台事件聚类、智能推荐和分类标签，帮助用户 3 分钟内掌握全网正在发生什么。

**一句话定位**：用 AI 读懂热搜 —— 不只是聚合，而是理解。

**MVP 定义**：今日热搜首版是一个无需登录、可公网访问的 AI 增强热榜聚合网站。采用**左侧导航栏 + 右侧内容区**的经典布局，包含**首页、个性推荐、平台**三个核心视图。首页通过「今日最热」轮播大卡片、「热点速览」小卡片和「综合热榜」三段式布局帮助用户 3 分钟内理解全网核心热点；个性推荐页基于预设兴趣标签和 AI 推荐结果提供主题化内容卡片；平台页展示各平台独立热榜。它稳定展示 8 个核心平台的实时热榜，并尽力接入抖音；AI 或单个平台不可用时，基础热榜浏览不受影响。首屏优先展示基础热榜，AI 区域允许异步补齐或降级。

## 目标用户

### 产品目标用户

* 想快速了解全网热点的上班族、学生、信息工作者

* 核心使用场景：晨间通勤 3 分钟速览、午休碎片时间刷热点

* 关注点：信息效率，一处看完全平台热点

### 项目展示受众

* 对 Vibe Coding / 全栈开发感兴趣的学习者

* 关注点：开发过程、技术实现、AI 集成方式

* 本类受众不影响产品功能设计决策

## 核心功能

### MVP 功能清单

#### F0：左侧导航栏 + 多视图架构

整站采用**左侧固定导航栏 + 右侧内容区**的布局，导航栏控制视图切换。

**导航栏结构（自上而下）**：

* 品牌标识区：Logo + 站名「今日热搜」+ 副标题

* 搜索框（占位，后续迭代实现搜索功能）

* **导航区**：

  * 首页 — 综合热点视图（默认激活）

  * 个性推荐 — AI 个性化推荐视图

  * 平台 — 各平台独立热榜视图

* **热门标签区**：科技、娱乐、体育、财经、社会（点击后跳转至个性推荐视图并自动筛选对应标签）

* 页脚信息

**视图切换行为**：

* 点击导航项切换右侧内容区，当前项高亮

* 视图切换时顶栏标题和副标题同步更新

* 移动端导航栏默认收起，点击汉堡按钮展开，带遮罩层

#### F1：首页视图（三段式布局）

首页视图自上而下分为三个区域：

##### F1a：今日最热（轮播大卡片）

* 位于首页**最顶部**，视觉最醒目的区域

* AI 从全平台热搜中筛选出 **5 个最值得关注的核心事件**，以轮播卡片形式展示

* 每张卡片展示：

  * **新闻配图**：全宽背景图，高度约 300px，底部渐变遮罩

  * **分类标签**：亮色药丸标签（如「科技 · AI」「社会 · 民生」）

  * **事件标题**：AI 生成的归纳性标题，大字号醒目展示

  * **AI 热门原因**：一段简短文字解释为什么这条新闻上了热搜（左侧带青色竖线的高亮区块），必须引用可解释依据（如「多平台同时登榜」「热度飙升」等）

  * **热度值 + 讨论平台数 + 趋势标签**

* **交互**：

  * 两侧箭头按钮手动切换，按钮为**窄长方形**（宽约 44px、高约 64px、圆角），默认**接近透明**（背景约 15% 不透明度），hover 时加深至约 65%；按钮定位于卡片内侧边缘，**不得遮挡标题、AI 热门原因等文字内容**

  * 底部圆点指示器，支持点击跳转

  * 自动轮播（5 秒间隔），用户操作后暂停

* 降级策略：AI 挂掉时该区域隐藏或显示「AI 推荐暂时不可用」，不影响下方热榜

##### F1b：热点速览（小卡片轮播）

* 位于「今日最热」下方

* 每页展示 **2 张小卡片**，与「今日最热」**同样的图片叠加文字覆盖式样式**

* 每张卡片展示：

  * 新闻配图（高度约 160px）+ 底部渐变遮罩

  * 分类标签（亮色药丸）

  * 事件标题

  * AI 一句话总结（热门原因）

  * 来源平台 + 热度值

* **交互**：两侧箭头按钮切换不同页（每页 2 张卡片）；箭头按钮样式与「今日最热」一致，为**窄长方形、接近透明、不遮挡文字内容**

* 数据来源：AI 从热搜中筛选的次级热点事件（不与今日最热重复）

##### F1c：综合热榜（两列排行榜）

* 位于首页**最下方**

* **两列并排**的排行榜列表，展示全平台聚合排名

* **序号连续不重复**：左列显示第 1\~10 名，右列显示第 11\~20 名（即全榜共 1\~20，不是两列各自 1\~10）

* 每条热搜展示：排名序号（1\~3 金银铜高亮）、标题、涉及平台小圆点、热度值、趋势箭头

* 排名 1\~3 视觉强调（金/银/铜色背景徽章）

**RankingItem 字段定义**（综合热榜条目，位于接口顶层 `ranking` 数组中）：

| 字段        | 类型                           | 说明                                    |
| --------- | ---------------------------- | ------------------------------------- |
| rank      | number                       | 全局排名 1\~20，序号连续不重复                    |
| title     | string                       | 聚合后的事件标题                              |
| url       | string                       | 原始链接（取热度最高的来源平台链接）                    |
| heat      | string                       | 综合热度值（如「1286万」）                       |
| platforms | string[]                     | 涉及平台标识列表（如 `["weibo", "toutiao", "zhihu"]`） |
| trend     | "up" \| "down" \| "flat"     | 趋势方向：上升 / 下降 / 持平                     |

**AI 输入字段**：

| 字段        | 来源   | 说明                         |
| --------- | ---- | -------------------------- |
| platform  | 平台标识 | weibo / zhihu / bilibili 等 |
| rank      | 热搜排名 | 数字                         |
| title     | 热搜标题 | 原始标题文本                     |
| heat      | 热度值  | 字符串，可能为空                   |
| url       | 原始链接 | 完整 URL                     |
| fetchedAt | 抓取时间 | ISO8601                    |

**AI 输出字段（今日最热 + 热点速览）**：

| 字段         | 类型                   | 说明                                           |
| ---------- | -------------------- | -------------------------------------------- |
| eventTitle | string               | AI 归纳的事件标题                                   |
| hotReason  | string               | AI 总结的热门原因（一段简短文字，引用可解释依据）                   |
| tag        | string               | 分类标签（如「科技 · AI」）                             |
| imageUrl   | string               | 配图 URL（AI 建议或编辑配置）                           |
| platforms  | array                | 涉及平台及排名，如 `[{"source": "weibo", "rank": 1}]` |
| heat       | string               | 综合热度值                                        |
| trend      | string               | 趋势标签（如「今晨登顶」「持续升温」）                          |
| section    | "featured" / "quick" | 归属区域：今日最热 or 热点速览                            |

**验收标准**：

* 今日最热输出 5 条事件，热点速览输出 8\~10 条事件，两者不重复

* AI 热门原因必须引用可解释依据，不能是空话

* AI 返回格式异常时后端兜底，不影响综合热榜展示

* AI 响应超时（>10s）时跳过，返回空推荐，综合热榜仍正常

* 综合热榜两列总条目不少于 15 条

#### F1d：个性推荐视图

* 通过左侧导航栏「个性推荐」进入

* 页面顶部为**标签筛选栏**：全部 / 科技 / 娱乐 / 体育 / 财经 / 社会 / 游戏 / 教育 / 国际 / 生活 / 其他（使用固定 10 类标签枚举，移动端横向滚动）+ 「我关注的平台」「我关注的标签」（后两者为占位按钮，后续迭代）

* 内容区采用**纵向排列的大卡片**，样式与「今日最热」轮播卡片一致：

  * 全宽背景图 + 底部渐变遮罩

  * **推荐原因标签**：区分「你关注 · 科技」（青色）和「相似主题」（紫色）两种类型

  * 事件标题（大字号）

  * **AI 推荐理由**：解释为什么为该用户推荐此条内容（左侧青色竖线高亮区块）

  * 热度值 + 来源平台 + 讨论平台数

* 标签筛选为纯前端过滤，点击标签后仅显示匹配卡片

* **数据来源**：AI 基于 MVP 预设关注标签 + 全平台热点相似主题生成推荐列表；首版不使用真实用户画像，不声称基于登录用户行为或相似用户协同过滤

* 降级策略：AI 不可用时显示「个性推荐暂时不可用，请查看首页综合热点」

**AI 输出字段（个性推荐）**：

| 字段            | 类型                   | 说明                  |
| ------------- | -------------------- | ------------------- |
| eventTitle    | string               | 事件标题                |
| reasonType    | "follow" / "similar" | 推荐类型：基于预设关注 or 相似主题 |
| reasonLabel   | string               | 推荐标签文案（如「你关注 · 科技」） |
| aiReason      | string               | AI 推荐理由详细文字         |
| imageUrl      | string               | 配图 URL              |
| platform      | string               | 主要来源平台              |
| platformCount | number               | 讨论平台数               |
| heat          | string               | 热度值                 |
| tags          | array                | 分类标签                |

#### F2：平台热榜卡片网格（平台视图）

* 通过左侧导航栏「平台」进入

* 8 个核心平台（微博、知乎、B站、澎湃、36氪、虎扑、GitHub、今日头条）各一张卡片

* 抖音为可降级平台：成功接入则展示，失败则隐藏或显示「数据源维护中」

* 每张卡片包含：

  * 平台图标 + 平台名称 + 榜单名称（如「微博 · 热搜榜」）

  * Top 15\~20 条热搜列表

  * 每条：排名、标题（可点击跳转原链接，新标签页打开）、热度值（有则显示，缺失则隐藏）

  * **AI 分类标签**：每条热搜旁显示 1\~2 个彩色小标签（如「科技」「娱乐」）

  * 底部显示「更新于 x 分钟前」

* 排名 1\~3 视觉强调（不同颜色/样式）

* 单平台失败时该卡片显示错误态 + 重试按钮，不影响其他卡片

* 原链接缺失时标题不可点击，显示为纯文本

#### F3：AI 分类标签筛选

* 固定标签枚举：`科技` `娱乐` `体育` `财经` `社会` `游戏` `教育` `国际` `生活` `其他`

* 每条热搜最多 2 个标签

* AI 无法分类时使用「其他」

* AI 返回非法标签（不在枚举内）时后端自动过滤

* 前端只展示固定枚举内的标签

* 平台视图提供完整标签筛选栏，个性推荐视图提供推荐内容标签筛选栏；首页不承担全局标签筛选，避免与三段式速览目标冲突

* 用户在平台视图点击某个标签后，所有平台卡片仅显示匹配该标签的热搜条目；用户在侧边栏点击热门标签时，跳转至个性推荐视图并筛选对应标签

* 点击「全部」恢复完整列表

* **标签筛选无结果时**：显示「该分类下暂无热搜」空状态提示

#### F4：数据接口（自建后端）

* `GET /api/hot` — 返回全部平台数据 + 综合热榜 + AI 推荐卡片 + 分类标签

* `GET /api/hot/:source` — 返回单平台数据

* source 枚举：weibo | zhihu | bilibili | douyin | thepaper | kr36 | hupu | github | toutiao

* 平台标识统一使用 `kr36` 表示 36氪；如后端或第三方源返回 `36kr`，进入业务响应前需映射为 `kr36`

* 无效 source 返回 404

#### F5：缓存机制

* 每个平台独立缓存，TTL 5\~10 分钟

* AI 推荐和分类标签与热搜数据同步缓存；首屏可先返回命中的基础热榜缓存，AI 数据为空时前端展示降级态

* **AI 数据补齐策略**：后端 `/api/hot` 为单次请求、同步返回模式——若缓存中基础热榜已就绪但 AI 尚未完成，后端先返回 `ai.available: false` + 基础数据，AI 结果在后台写入缓存；前端在首次加载若发现 `ai.available: false`，可在 30 秒后自动重新请求一次 `/api/hot` 尝试获取 AI 数据（仅重试一次，不轮询）。MVP 不额外新增 `/api/ai` 接口

* 页面展示「更新于 x 分钟前」（基于 updatedAt 计算相对时间）

* 开发环境支持 `?refresh=1` 强制跳过缓存

* 缓存过期但新一轮抓取失败时：返回过期缓存数据并标注「数据可能已过期」

#### F6：异常处理与降级

| 异常场景            | 处理方式                           |
| --------------- | ------------------------------ |
| 单平台抓取失败         | 该卡片显示错误提示 + 重试按钮，其他卡片正常        |
| 抖音接入失败          | 隐藏卡片或显示「数据源维护中」                |
| AI 服务不可用        | AI 推荐卡片隐藏或显示占位提示，标签显示为空，热搜正常   |
| AI 返回 JSON 格式异常 | 后端兜底，丢弃异常数据，AI 区域降级            |
| 后端整体不可用         | 前端显示全局错误页                      |
| 首次加载中           | 骨架屏或 loading 动画                |
| 标签筛选无结果         | 显示「该分类下暂无热搜」                   |
| 平台返回空列表         | 该卡片显示「暂无数据」                    |
| 部分热搜没有标签        | 正常显示热搜条目，标签位置留空                |
| 用户点击刷新后仍失败      | 保留旧数据，顶部显示轻量提示「刷新失败，显示的是之前的数据」 |

#### F7：刷新按钮

* 顶栏右侧放置刷新按钮

* 普通点击：重新请求 `/api/hot`，走后端缓存（不强制绕过）

* 刷新中显示 loading 状态（按钮旋转或禁用）

* 刷新成功：更新数据和「更新于」时间

* 刷新失败：保留旧数据，显示轻量 toast 提示

#### F8：响应式布局

* 桌面端（>1024px）：侧边栏固定显示（200px 宽），首页轮播高度 300px，热点速览 2 列，综合热榜 2 列，平台卡片 3 列网格

* 平板端（768\~1024px）：侧边栏固定显示，平台卡片 2 列，其余同桌面

* 手机端（<768px）：侧边栏默认隐藏（点击汉堡按钮展开 + 遮罩层），内容区全宽；轮播高度缩小至 220px；热点速览 1 列；综合热榜 1 列；平台卡片 1 列；个性推荐卡片全宽

#### F9：页脚与合规

* 页脚信息置于侧边栏底部

* 站点名称 + 简介

* 声明：本站为个人学习项目，数据来源于各平台公开信息，非官方

* 所有标题点击跳转到来源平台原文

* 更新频率说明（约 5~10 分钟）

* 侵权联系方式（MVP 暂写 `contact@minihotub.com`，上线前替换为真实邮箱）

* AI 内容标注：「AI 推荐和标签由 AI 自动生成，仅供参考，本站不对 AI 生成内容作事实保证」

* 图片版权策略：MVP 不抓取来源站正文图片；AI 卡片优先使用自有图片、开源图库、平台默认封面或分类默认封面

* 数据抓取边界：遵守目标平台公开访问规则，控制抓取频率，不绕过登录、付费墙或明显反爬限制；数据源不可稳定访问时进入降级态

* 下架处理：收到权利人或平台反馈后，可移除对应链接、标题、图片或平台数据源

### 本期不做

| 功能         | 不做原因                              |
| ---------- | --------------------------------- |
| 小红书平台      | 无公开 API，反爬极高，MVP 阶段风险不可控          |
| 用户登录/注册    | 纯浏览型工具，登录增加复杂度且阻碍即开即用体验           |
| 历史热度回溯     | 需持久化数据库，存储成本高，MVP 只展示实时数据         |
| 站内搜索       | 需全文索引，工程量大，标签筛选可满足基本过滤需求          |
| 个性化排序（登录态） | MVP 个性推荐基于预设默认标签，真正的个性化依赖登录态，后续迭代 |

## 界面设计要求

### 整体风格

* 深色科技风，信息密度高，兼具科技感与阅读舒适度

* 深色背景（#0b0f19），卡片深蓝底（#151c2c），青色（#22d3ee）为主强调色

* 左侧固定导航栏（200px），右侧内容区 max-width 约 1100px

### 卡片内细节

* **今日最热 / 热点速览 / 个性推荐卡片**：全宽配图 + 底部渐变遮罩叠加文字信息；AI 摘要区使用左侧青色竖线 + 半透明背景高亮

* **综合热榜 / 平台热榜**：排名 1\~3 金/银/铜色圆角数字徽章，排名 4+ 灰色普通数字

* AI 标签：小圆角彩色药丸（不同类别不同颜色），来自固定枚举

* 热度值：红色（#f43f5e）等宽字体，右对齐，缺失时隐藏

* 标题：白色文字（深色主题），hover 时卡片整体上浮 + 发光边框

## 技术栈

* 前端：React + TypeScript + Vite + CSS Modules

* 后端：Node.js + Express + TypeScript

* AI：DeepSeek V3.2 API

* 部署：不锁死方案，Vercel + Railway 为参考示例，可根据技术设计调整
